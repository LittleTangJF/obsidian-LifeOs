### 1. GET和POST的请求的区别

- get不会对服务器资源产生影响，post会
- 发送报文：请求体get没有，post有
- 安全性：get不安全，历史记录
- 参数类型：post支持更多参数类型
### 2.HTTP 1.1 和 HTTP 2.0 的区别？

- **二进制协议**：统一为帧，是多路复用的基础，详细是报文的头信息和数据体都是二进制，而1.1中==头信息==是ASCII码
- **多路复用****：HTTP/2 实现了多路复用在一个连接里，客户端和服务器都可以同时发送多个请求或回应
- **数据流****：HTTP/2 使用了数据流的概念，HTTP/2 将每个请求或回应的所有数据包，称为一个数据流，每个数据流都有一个独一无二的编号==区分是哪个请求的==
- **头信息压缩****：HTTP/2 实现了头信息压缩，由于 HTTP 1.1 协议不带状态，每次请求都必须附上所有信息。所以，请求的很多字段都是重复的，比如 Cookie 和 User Agent ，一模一样的内容，每次请求都必须附带，这会浪费很多带宽，也影响速度。HTTP/2 对这一点做了优化，引入了头信息压缩机制。==gzip==
- **服务器推送**：HTTP/2 允许服务器未经请求，主动向客户端发送资源，这叫做服务器推送。主动推送的是==静态资源==

- 提升传输可靠性

### 3.HTTP和HTTPS协议的区别

- 安全性:HTTPS则是具有安全性的SSL加密传输协议,而http是明文传输
- 端口：HTTP协议端口是80，HTTPS协议端口是443
- 无状态：HTTP协议连接很简单，是无状态的，HTTPS协议身份认证的网络协议，比HTTP更加安全

###  **TCP三次握手**
==连接建立==
1. 客户端发送SYN 带序列号seq=j
2. 服务端接收客户端 SYN ACK=j+1 发送自己的SYN包seq=k
3. 客户端接收服务端 ACK=j+1和seq=k+1，发送ACK包K+1
4. 服务端接收客户端ACK=K+1

首先协商序列号，保证连接可靠性 ；防止有失效连接突然到服务端，比如网络延迟
==连接关闭==
  客户端                                   服务端
1. FIN=U
2. 接受ACK=U+1                  发送ACK=U+1
3.                                          发送FIN=W
4. 发送ACK=W+1                 接收ACK=W+1

### DNS 协议是什么

DNS 是域名系统 (Domain Name System) 的缩写

完整DNS解析过程
1. **浏览器的缓存**中查找对应的IP地址，如果查找到直接返回
2. 将请求发送给**本地DNS服务器**，在本地域名服务器缓存中查询
3. 本地DNS服务器向**根域名服务器**发送请求---返回顶级域名服务器地址
4. 本地DNS服务器向**顶级域名服务器**（.com）发送请求----返回下一级的权威域名服务器的地址
5. 本地DNS服务器向**权威域名服务器**（.baidu）发送请求---返回域名服务器返回对应的结果
